# Rest-Free 定时休息提醒 PC 应用 — 需求文档

> 版本：v1.0（MVP）
> 平台：Windows 10 / 11（x64）
> 技术栈：Electron + Vue 3 + TypeScript + electron-vite

---

## 1. 项目背景与目标

### 1.1 背景
长时间坐在电脑前工作/学习会导致颈椎、腰椎、视力、代谢等多方面健康风险。常见的健康建议是：每 30~60 分钟起身活动一次，喝水、伸展、远眺。

### 1.2 目标
开发一款**轻量、常驻托盘、可多任务并行**的桌面休息提醒应用 Rest-Free：

1. 支持创建多个定时提醒任务，每个任务独立设置「开始时间 / 提醒间隔 / 提醒文案 / 提醒位置」；
2. 提醒弹出后用户可选择「立即休息」或「稍后休息（默认 5 分钟后再次提醒）」；
3. 所有配置以 `config.json` 持久化到用户数据目录，**应用升级、重装（不勾选删除配置）不丢失**；
4. 开机自启、最小化到托盘，对工作流零打扰。

### 1.3 非目标（v1.0 不做）
- 多平台（macOS / Linux）适配，仅保证 Windows；
- 账号系统、云同步；
- 手机 App / 多端联动；
- 健康数据统计报表（列入后续迭代）。

## 2. 术语定义

| 术语 | 含义 |
| --- | --- |
| 任务（Task） | 一条独立的定时提醒规则 |
| 触发（Fire） | 到达预定时刻，弹出提醒窗口 |
| 立即休息（Rest Now） | 用户确认休息，进入全屏休息倒计时 |
| 稍后休息（Snooze） | 推迟 `snoozeMinutes`（默认 5 分钟）后再次提醒 |
| 忽略（Dismiss） | 关闭提醒窗口，不进入休息，等待下一次按间隔触发 |
| 勿扰模式（DND） | 全局开关，开启期间抑制所有提醒触发 |
| 错过补偿 | 系统睡眠/休眠唤醒后，对已越期未触发的提醒进行补触发 |

## 3. 用户故事

1. 作为一名办公室职员，我希望每 45 分钟被提醒「起来伸展一下」，并且提醒出现在**屏幕正中间**，确保我不会错过；
2. 作为一名程序员，我希望每 60 分钟提醒「喝水」，位置在**屏幕右下角**，不遮挡代码编辑器；
3. 作为一名设计师，我希望每 30 分钟提醒「远眺 20 秒」，位置在**屏幕上方**，像通知条一样不打断操作；
4. 当我正在专注写文档时，我希望点「稍后休息」，5 分钟后应用再提醒我一次；
5. 当我点击「立即休息」时，我希望出现一个全屏柔和遮罩并倒计时，倒计时结束自动消失；
6. 我希望应用开机自启并常驻托盘，不占任务栏；
7. 我希望临时开会时不被打扰，可以开启「勿扰模式」；
8. 我希望升级应用版本后，之前设置的任务还在。

## 4. 功能需求

### 4.1 任务管理（FR-1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-1.1 | 新建任务 | 字段见下表 |
| FR-1.2 | 编辑任务 | 表单回显当前值 |
| FR-1.3 | 删除任务 | 二次确认 |
| FR-1.4 | 启用/停用 | 卡片开关，停用后不参与调度 |
| FR-1.5 | 多任务并行 | 任务数量不设上限，调度互相独立 |
| FR-1.6 | 下次触发时间预览 | 卡片上展示「下次提醒 HH:mm」 |

**任务字段：**

| 字段 | 类型 | 约束 | 默认值 |
| --- | --- | --- | --- |
| id | string | 主键，`crypto.randomUUID()` | 自动生成 |
| name | string | 1~30 字，必填 | — |
| startTime | string | `HH:mm`，每日首次触发时刻 | `09:00` |
| intervalMinutes | number | 1 ~ 1440 分钟 | `45` |
| message | string | 1~60 字，提醒文案 | — |
| position | enum | `top` / `center` / `bottom-right` | `center` |
| enabled | boolean | 是否参与调度 | `true` |
| createdAt / updatedAt | number | 时间戳（ms） | 自动维护 |

### 4.2 调度规则（FR-2）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-2.1 | 每日对齐 | 每个任务每天从 `startTime` 开始第一次触发，之后每 `intervalMinutes` 触发一次；到达次日 `startTime` 时重新对齐，保证每天首次触发时刻固定 |
| FR-2.2 | 精度 | 使用动态 `setTimeout` 链而非轮询，触发误差 < 2 秒 |
| FR-2.3 | 错过补偿 | 系统睡眠/挂起恢复后，若某任务触发时刻已过但未触发，则在唤醒后立即补触发一次，随后回到正常节奏 |
| FR-2.4 | Snooze | 用户点「稍后休息」后，该任务下一次触发改为 `now + snoozeMinutes`，且**仅覆盖一次**，之后再回到常规节奏 |
| FR-2.5 | 勿扰模式 | 开启期间不弹窗、不推进 `nextFireAt`，关闭后自然补触发 |
| FR-2.6 | 休息抑制 | 进入「立即休息」倒计时期间，其他任务的触发被暂缓，休息结束后恢复 |
| FR-2.7 | 状态持久化 | 调度状态（各任务 `nextFireAt`）写入 `state.json`，重启后不丢节奏 |
| FR-2.8 | 状态实时刷新 | 每次触发提醒 / snooze / 删除任务后，主进程广播 `schedule:changed`，主窗口「下次提醒」立即刷新为下一次触发时刻（不需用户手动操作） |

### 4.3 提醒呈现（FR-3）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-3.1 | 提醒窗口 | 无边框、透明背景、始终置顶、不占任务栏；卡片为 Element Message 风格：浅绿底 `#f0f9eb`、细边框 `#e1f3d8`、圆角 6px、单行紧凑布局（约 40px 高） |
| FR-3.2 | 位置-上方 | 宽 520px，水平居中，贴屏幕顶部，从上往下滑入动画 |
| FR-3.3 | 位置-正中间 | 宽 560px，屏幕正中央，淡入 + 轻微放大动画 |
| FR-3.4 | 位置-右下角 | 宽 480px，距右/下各 16px（避开任务栏，基于工作区计算），从右下滑入 |
| FR-3.5 | 多显示器 | 优先使用鼠标当前所在屏幕，取不到时用主屏 |
| FR-3.6 | 内容 | 单行：`图标 + 任务名：提醒文案（超长省略，hover 显示全文）+ 文字按钮「立即休息 / 晚 N 分钟」+ 关闭钮（= 忽略）` |
| FR-3.7 | 去重 | 同一任务提醒窗口已存在时不重复弹出（聚焦已有窗口） |
| FR-3.8 | 声音（可选） | 预留开关，默认关闭 |
| FR-3.9 | 高度自适应 | 渲染层测量内容高度并上报，主进程钳制到 44~220px 后 `setBounds`（正中间位置按新高度重新居中），窗口在收到首次上报后才显示，避免空卡跳动 |

### 4.4 休息流程（FR-4）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-4.1 | 立即休息 | 关闭提醒窗口，打开全屏休息遮罩 |
| FR-4.2 | 休息遮罩 | 半透明柔和遮罩 + 居中卡片：任务文案、倒计时 `mm:ss`、「我休息好了」按钮、「+5 分钟」按钮 |
| FR-4.3 | 倒计时 | 默认 `restMinutes`（默认 5 分钟），主进程每秒驱动，渲染层只负责显示 |
| FR-4.4 | 结束方式 | 倒计时归零自动关闭；或用户点「我休息好了」/ 按 `Esc` 提前结束 |
| FR-4.5 | 休息延长 | 「+5 分钟」在当前剩余时间上加 5 分钟 |

### 4.5 系统集成（FR-5）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-5.1 | 托盘常驻 | 关闭主窗口不退出，最小化到托盘 |
| FR-5.2 | 托盘菜单 | 打开主界面 / 勿扰模式开关 / 退出 |
| FR-5.3 | 开机自启 | 设置项控制，调用系统登录项 API |
| FR-5.4 | 单实例 | 重复启动时聚焦已有实例，不打开多个进程 |
| FR-5.5 | 主窗口 | 默认尺寸 960×680，最小 800×560，自定义标题栏 |

### 4.6 配置持久化（FR-6）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-6.1 | 存储位置 | `%APPDATA%/rest-free/config.json`（`app.getPath('userData')`），安装/升级/便携运行均不影响 |
| FR-6.2 | 存储内容 | 任务列表 + 全局设置，含 `version` 字段 |
| FR-6.3 | 原子写入 | 先写 `.tmp` 再 `rename`，防止崩溃写一半 |
| FR-6.4 | 防抖保存 | 连续变更合并为一次落盘（500ms），退出时强制 flush |
| FR-6.5 | 容错 | 文件损坏/字段缺失时与默认配置深合并后自动修复，不崩溃 |
| FR-6.6 | 版本迁移 | `version` 升级时按迁移函数逐版升级 |
| FR-6.7 | 导入/导出 | 支持导出配置为文件、从文件导入（v1.1，MVP 预留入口） |

### 4.7 默认配置与版本升级（FR-7）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-7.1 | 开箱即用 | 首次启动自动注入 2 条默认任务，用户零配置即可使用 |
| FR-7.2 | 默认任务 | ①「拉伸放松」：每 15 分钟，位置屏幕上方；②「喝水 · 上厕所」：每 45 分钟，位置屏幕正中间 |
| FR-7.3 | 用户优先 | 用户修改默认任务（编辑/停用）后标记 `customized`，此后版本升级不再覆盖该任务 |
| FR-7.4 | 删除不复活 | 用户删除默认任务后记入 `removedDefaults`，版本升级时不重新添加 |
| FR-7.5 | 随版本更新 | `config.json` 记录 `defaultsVersion`；升级 `DEFAULTS_VERSION` 后，未定制的默认任务在下次启动时更新为新模板 |
| FR-7.6 | UI 标识 | 默认任务卡片显示「默认」徽标；删除时确认文案提示"版本更新不会再自动添加" |

**默认任务定义：**

| id | 名称 | startTime | intervalMinutes | position |
| --- | --- | --- | --- | --- |
| `default-stretch` | 拉伸放松 | 09:00 | 15 | top |
| `default-water` | 喝水 · 上厕所 | 09:00 | 45 | center |

**合并算法（启动时执行）：**

```
if (config.defaultsVersion >= DEFAULTS_VERSION) return
for (tpl of DEFAULT_TASKS):
    if (tpl.id in removedDefaults) continue          # 用户删过，不加回
    existing = tasks.find(tpl.id)
    if (!existing)            insert(tpl)             # 新默认规则
    else if (!customized)     if (business fields changed) overwrite(tpl)  # 默认随版本更新
    # customized → 保留用户值
config.defaultsVersion = DEFAULTS_VERSION
```

## 5. 非功能需求（NFR）

| 编号 | 需求 | 指标 |
| --- | --- | --- |
| NFR-1 | 常驻内存 | 空闲时内存占用 < 200MB |
| NFR-2 | CPU | 空闲时 CPU 占用 ≈ 0（事件驱动，无轮询循环） |
| NFR-3 | 触发精度 | 误差 < 2 秒 |
| NFR-4 | 稳定性 | 主进程未捕获异常不影响调度器，异常后自动重启窗口 |
| NFR-5 | 安全 | `contextIsolation: true`、`nodeIntegration: false`，渲染层仅通过 contextBridge 白名单 API 通信 |
| NFR-6 | 兼容性 | Windows 10 1809+ / Windows 11；125%/150% DPI 缩放正常 |
| NFR-7 | 日志 | `userData/logs/app.log`，超过 1MB 自动截断，便于线上问题排查 |

## 6. 架构设计

```
┌────────────────────────────────────────────────────────┐
│ 主进程 Main Process                                     │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────┐   │
│  │ ConfigStore│  │ Scheduler │  │ ReminderManager  │   │
│  │ config.json│  │ nextFireAt│  │ 提醒窗口 x N      │   │
│  │ state.json │  │ DND/休息  │  │ 休息遮罩窗口 x 1  │   │
│  └───────────┘  └───────────┘  └──────────────────┘   │
│  ┌───────────┐  ┌───────────┐  ┌──────────────────┐   │
│  │ Tray      │  │ IPC 注册  │  │ AutoStart        │   │
│  └───────────┘  └───────────┘  └──────────────────┘   │
├────────────────────────────────────────────────────────┤
│ 预加载 Preload：contextBridge 白名单 API                 │
├────────────────────────────────────────────────────────┤
│ 渲染层 Renderer                                         │
│  ┌────────────────────┐      ┌─────────────────────┐  │
│  │ 主窗口 Vue3 任务管理 │      │ 提醒/休息窗口（轻 DOM）│  │
│  └────────────────────┘      └─────────────────────┘  │
└────────────────────────────────────────────────────────┘
```

**模块职责：**

| 模块 | 职责 |
| --- | --- |
| `configStore.ts` | config.json / state.json 读写、深合并、原子写、防抖、版本迁移 |
| `scheduler.ts` | 计算 `nextFireAt`、动态 setTimeout、错过补偿、DND/休息抑制、snooze |
| `reminderWindows.ts` | 提醒窗口创建/定位/复用/关闭，休息遮罩窗口与倒计时驱动 |
| `ipc.ts` | 渲染层 ↔ 主进程通道，配置变更唯一写入口 |
| `tray.ts` | 托盘图标与菜单 |

**数据流：** 渲染层操作 → IPC → ConfigStore 落盘 → 广播 `config:changed` → Scheduler 重算。

## 8. 边界与异常处理

| 场景 | 策略 |
| --- | --- |
| 系统睡眠错过触发 | 唤醒后 tick 检测到 `now >= nextFireAt`，立即补触发一次，随后按算法推进 |
| 配置损坏 | JSON 解析失败 → 备份为 `config.corrupt.json`，以默认配置重建 |
| 磁盘写入失败 | 记日志并内存保留，下次变更重试，不崩溃 |
| 任务被删但窗口开着 | 关闭窗口并释放引用 |
| 时间被用户修改 | 以 tick 时实际系统时间为准，自然校正 |
| 23:59 附近的触发 | 次日 startTime 对齐，不会出现「跨天双触发」 |
| snooze 中任务被编辑 | 保存后按新参数重算 nextFireAt |
| 勿扰模式开启期间到达触发点 | 不弹窗也不推进 nextFireAt，关闭勿扰后补触发 |

## 10. 验收标准

1. 创建 3 个不同位置/间隔的任务，均能按时弹出，位置与设计一致；
2. 点「稍后休息」后 5 分钟（±10s）再次弹出同一任务；
3. 点「立即休息」后出现全屏倒计时，可提前结束，结束后调度恢复正常；
4. 修改配置后 `%APPDATA%/rest-free/config.json` 内容正确更新；
5. 覆盖安装/升级后任务与设置保留；
6. 开机自启开启后重启电脑，应用自动启动并在托盘可见；
7. 闲置 10 分钟，进程 CPU 占用 < 1%。
